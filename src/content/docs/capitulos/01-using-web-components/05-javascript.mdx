## Introducción

Un Web Component es un elemento DOM con una API adicional. No necesitas un bus global para configurarlo ni un framework para escuchar sus eventos. La dificultad está en conocer qué acepta el contrato y cuándo puedes observar su resultado.

Esta lección introduce el consumo. La conversión completa de valores, los modelos de reflexión y el diseño de contratos se desarrollarán en PR-03. Aquí usamos una tarjeta con reglas pequeñas y explícitas para poder experimentar sin ambigüedad.

## Objetivos

- Seleccionar un elemento y distinguir atributo, propiedad y método.
- Recibir un `CustomEvent` con payload validado.
- Observar propagación y limpiar listeners respetando su propietario.

## API pública de la tarjeta

| Entrada o salida                 | Tipo y valor inicial                   | Efecto                                                          |
| -------------------------------- | -------------------------------------- | --------------------------------------------------------------- |
| `heading` / atributo `heading`   | `string`, “Using Web Components”       | Texto del encabezado; refleja durante el ciclo Lit              |
| `compact` / atributo `compact`   | `boolean`, `false`                     | Densidad reducida; el atributo es por presencia                 |
| `reader`                         | `{ name: string }`, “Visitante”        | Propiedad rica; no tiene atributo equivalente                   |
| `selected` / atributo `selected` | `boolean`, `false`                     | Estado seleccionado y `aria-pressed`                            |
| `reset()`                        | Método sin argumentos                  | Desmarca sin emitir eventos                                     |
| `lesson-select`                  | `CustomEvent<{ heading, readerName }>` | Se emite al activar el botón; `bubbles` y `composed` son `true` |

Los nombres del payload son cadenas. Eliminar `heading` o asignarle un valor vacío restablece el encabezado por defecto; el evento conserva así su contrato de texto. `reader` normaliza una entrada inválida a “Visitante”, recorta espacios y limita el nombre a 80 caracteres. Asignar un objeto nuevo expresa un cambio detectable; mutar `card.reader.name` no solicita por sí solo una actualización Lit. El consumidor debe tratar el valor como dato y asignar una nueva referencia.

## Atributo frente a propiedad

`setAttribute()` y `getAttribute()` trabajan con cadenas o ausencia (`null`). Las propiedades son miembros JavaScript y pueden contener objetos. Que sus nombres coincidan no implica que se sincronicen: lo decide el componente. En este ejemplo Lit refleja algunas propiedades; no todos los Web Components lo hacen.

```ts
await customElements.whenDefined('lab-reading-card');
const card = document.querySelector('lab-reading-card');
if (card) {
  card.setAttribute('heading', 'Lectura de hoy');
  card.reader = { name: 'Ada' };
  card.compact = true;
  await card.updateComplete; // API de Lit; no forma parte de HTMLElement.
}
```

El tipo del selector procede del mapa de etiquetas declarado por el módulo. Si seleccionas una cadena dinámica, debes comprobar el tipo o la capacidad antes de llamar métodos. `querySelector()` también puede devolver `null`; no asumas que cualquier página contiene la demo.

## Eventos y fronteras

`CustomEvent` pertenece al navegador. Su campo `detail` lleva el payload acordado; Lit no necesita un sistema de eventos paralelo. El nombre distingue mayúsculas y minúsculas. El consumidor debe suscribirse a `lesson-select`, no a un nombre parecido inventado por su framework.

`bubbles` permite el recorrido por ancestros en la fase de burbujeo. `composed` permite cruzar fronteras Shadow DOM en el recorrido del evento. Son decisiones independientes: no conviertas `composed` en sinónimo de “burbujea”. El retargeting puede hacer que `event.target` visto desde fuera sea el host; usa el payload acordado en lugar de depender de un botón interno. La semántica completa del recorrido está en el [estándar DOM](https://dom.spec.whatwg.org/#events).

## Suscripción y limpieza

```ts
const controller = new AbortController();
card.addEventListener('lesson-select', handleSelection, {
  signal: controller.signal,
});
// Al desmontar este consumidor:
controller.abort();
```

`handleSelection` debe comprobar `event instanceof CustomEvent` y la forma de `detail` si no puede confiar en el origen. El módulo `selection-contract.ts` muestra esa comprobación sin convertir cualquier evento con un cast. El consumidor Astro utiliza funciones estables y `removeEventListener()` al desconectar; Lit gestiona los listeners declarados en su propio template.

Un listener de un nodo que posees no exige el mismo tratamiento que uno instalado en `window`. Lo importante es quién mantiene vivo a quién y si volver a conectar duplica suscripciones. Conserva la función original: dos funciones flecha escritas igual siguen siendo objetos diferentes.

## Errores habituales

- Escribir `reader="{...}"` esperando que aparezca un objeto.
- Leer el DOM inmediatamente después de una asignación Lit.
- Confundir el retorno de un método con un evento de usuario.
- Depender de `shadowRoot.querySelector('button')` para integrar la aplicación.
- Escuchar en cada render y olvidar retirar el listener anterior.

## Resumen y autoevaluación

El contrato se consume con DOM APIs: cadenas para atributos, datos para propiedades, acciones explícitas mediante métodos y notificaciones mediante eventos. Comprueba el momento de actualización que promete cada implementación.

**Entrevista:** ¿por qué `setAttribute('compact', 'false')` puede compactar la tarjeta? Porque su conversor booleano interpreta presencia. Para retirarlo usa `removeAttribute('compact')` o asigna `card.compact = false`.
