## Hallazgos pendientes

- **P1, validación externa:** ejecutar `pnpm check` en Ubuntu 24.04 o un sistema compatible con Playwright 1.64.1. Faltan responsive a **320, 375, 768, 1280 y 1440 px**, errores de consola, axe, teclado en navegador, búsqueda Pagefind, Mermaid, progreso local, capturas y revisión visual. La suite contempla estos escenarios; ninguno se presenta como aprobado por haber sido escrito o listado. Docker no tiene daemon disponible; no hay un runner compatible acreditado en esta sesión.
- **P2, dependencias:** nueve avisos en tooling, incluidos uno crítico y cuatro altos. Las condiciones notificadas no están habilitadas por los scripts actuales; esto es análisis de alcance por configuración, no una prueba de explotación. Revisar actualizaciones compatibles y seguimiento upstream en [seguridad](security.md). No hay supresiones.
- **P2, rendimiento:** el build avisa de chunks mayores de 500 kB. En los artefactos Mermaid, `elk` mide 1.462.826 bytes (446.832 gzip) y otro chunk 629.040 bytes (125.103 gzip). Pertenecen al grafo de dependencias de Mermaid; el script de diagramas solo se incluye en recursos. No se midió qué chunks se descargan al abrir el diagrama, ni red, ejecución o Core Web Vitals. Conviene medir la página de recursos antes de decidir una reducción de Mermaid. No se aplican optimizaciones especulativas.
- **P3, publicación:** el build omite sitemap porque todavía no hay dominio `site`; configurarlo cuando exista un destino autorizado. También avisa de colección i18n ausente y colisión de `/404` con la ruta documental; se genera `404.html` con el contenido personalizado. No se inventa un dominio para silenciar avisos.

## Arquitectura, seguridad y experiencia

Astro/Starlight genera contenido estático; portal y composición están en componentes Astro, el índice editorial en datos y los ejemplos nativo/Lit en módulos independientes del navegador. No se evalúa `HTMLElement` desde frontmatter. TypeScript es estricto y los decorators experimentales de Lit son coherentes con `useDefineForClassFields: false`.

Los contadores comparten conversión y eventos sin compartir estado. El nativo modifica sus nodos propios y recupera propiedades previas al upgrade; Lit mantiene `render()` puro y actualización asíncrona. Los listeners del laboratorio se retiran al desconectar y el registro limita sus filas. Las pruebas verifican eventos `bubbles`/`composed`, asignaciones silenciosas y reconexión. El progreso valida el esquema y comunica fallos de almacenamiento; su persistencia efectiva sigue pendiente de E2E.

Se conserva texto escapado, fuentes locales revisadas y Mermaid en modo estricto. `unsafeCSS` recibe una constante local; no hay ejecución de código externo editable ni telemetría añadida por la aplicación. Se revisaron licencias y engines de las dependencias directas instaladas: MIT, BSD-3-Clause, Apache-2.0 y MPL-2.0; no se incorporan paquetes nuevos.

El diseño tiene identidad propia, tokens claros/oscuros, rejillas adaptables, propiedades lógicas, foco visible y estilos para reduced motion y forced colors. **La calidad visual final no está acreditada:** sin navegador no hay capturas reales, evaluación de reflow, contraste ni anuncios con lector de pantalla. Tampoco se realizó zoom manual ni se declara conformidad WCAG completa.

La CI usa Ubuntu 24.04, instalación congelada, caché pnpm, permisos de lectura, todas las puertas y tres motores con reportes en fallo. La configuración Vercel corresponde a salida estática `dist` y mantiene despliegues Git desactivados. No se ejecutó CI remota ni un build dentro de Vercel; no se certifica hosting efectivo.
